## value.html（遞迴）
輸入 dict `{v: <值>, depth: <int>}`：
- 字串／數字 → `markdownify` 輸出（段落）
- 清單 → `<ul>`，每項遞迴
- map → `<dl>`，每個 key 用下列中文標籤（查不到就原樣顯示 key），value 遞迴
  標籤：name 名稱、detail 說明、cue 口令、how_to 做法、certainty 確定性、why 為什麼、better 更好的說法、note 備註、text 內容、summary 摘要、population 族群、structures 結構、mechanism 機制、prevention 預防、management 處理、risk_factors 風險因子、epidemiology 流行病學、observation 觀察、intervention 介入、quant 量化參考、indicator 指標
- 以下 key 一律不輸出：`id`、`source`、`sources`、`source_ids`、`cross_ref`、`cross_ref_ids`、`links`、`observation_basis`、`notes`、`*_ids`（任何以 `_ids` 結尾者）
- 值為空（空字串、空清單、空 map、nil）時什麼都不輸出，也不輸出其標籤
- depth 超過 4 就停止遞迴

## unit.html 版面（依序，全部在 `<article class="page unit">` 內）
1. `<p class="unit-kicker">`：泳式中文名（若有）· 類別中文名（category_name，若有）· type 中文名（move 動作、drill 練習、tech 技術分析、error 教學誤區、problem 找問題、injury 運動傷害、level 水感級別、psy 心理主題、psyc 心理概念）
2. `<h1>` 標題
3. **一句話**（`<p class="unit-hook read">`）：
   - error：「很多人以為：」＋ misconception，下一段「其實：」＋ correct_concept（兩段都要，這是誤區頁最吸引人的部分）
   - 其他：hook 欄位（見 units.<id>.hook；若 record 的原欄位更完整就用原欄位全文）
4. **是什麼／怎麼做**（`<section class="layer layer-what">`，h2「怎麼做」或「是什麼」）依 type：
   - move：cue_bad「常見說法」→ cue_why「為什麼不好」→ cue_good「更好的說法」三格並列（手機改直排）；boundary「邊界」；l「對應級別」
   - drill：how_to 編號清單；equipment「器材」（空就寫「不需器材」）；perception_goal「要感覺到的」；success_signal「做對的訊號」；failure_signal「做錯的訊號」
   - tech：practical_implication；perception_signal「感覺訊號」
   - problem：observable「看得到的現象」
   - injury：mechanism、prevention、management（用 value.html）
   - level：description、indicators、methods（每個 method 顯示 name 粗體 + detail + cue）、milestone「里程碑」、stagnation「停滯訊號」
   - psy：premise、when_zh；並列出其 concepts（從 in 邊 rel=part_of 取得）連結
   - psyc：phenomenon；misconception_refs（每項：常見說法 cue／為什麼 why／更好的說法 better）；intervention_refs（name + certainty + how_to）
5. **為什麼**（`<section class="layer layer-why">`，h2「為什麼」）：move→physical、lnote；error→physical_reason、perception_impact；tech→mechanism；problem→mechanism_summary；injury→epidemiology、risk_factors
6. **證據與來源**：`<details class="layer layer-evidence">`，summary「證據與來源」；內容 evidence（value.html）＋ source_ids 原樣列出（不查表，每個 id 一行 `<code>`）＋ certainty（若有）。若網址 hash 指到它則展開（可省略 JS，用 `id="evidence"` 即可）
7. **接著看**：`{{ partial "vortex/next-read.html" (dict "id" <id> "data" <vortex_links>) }}`

每個 layer 只有在裡面至少一個欄位有值時才輸出（含標題）。

## next-read.html（接著看）
合併 `out.<id>` 與 `in.<id>` 的所有對方 unit（去重），**依對方 type 分組**，組標題與順序：
drill「怎麼練這個」→ move「相關動作」→ error「常見的錯誤想法」→ tech「背後的機制」→ problem「練不起來時」→ level「這是哪一級的事」→ injury「相關傷害風險」→ psy/psyc「心理層」。
每組：`<h3>` 標題 ＋ 最多 4 條 `<a class="nr-item">`（標題 ＋ 下一行 `muted` 的 hook）；超過 4 條時其餘放 `<details><summary>看全部 N 條</summary>…</details>`。
整塊包在 `<section class="next-read" aria-labelledby="nr-h"><h2 id="nr-h">接著看</h2>…</section>`；沒有任何連結就整塊不輸出。
另外在 next-read 最後加一行連回該單位的泳式頁（若有 stroke）與集合清單頁：「看{泳式}的全部內容 →」「看全部{集合名} →」。

## unit.css 要點
- `.unit-kicker` 用 `--fs-s`、`--series` 色、字重 600
- `.unit-hook` 用 `--fs-l`、襯線、行高 1.7，與 h1 間距 `--s2`
- move 的三格：桌機 `grid-template-columns: repeat(3, 1fr)`，600px 以下單欄；每格上方一條 2px `--rule` 線，「更好的說法」那格線改 `--series`
- `.nr-item`：block、`min-height: var(--tap)`、上下 `--s1` 內距、下方 1px `--rule` 分隔、標題 `--ink` 字重 600、無底線；hover 時標題加底線
- 不准用卡片框、陰影
