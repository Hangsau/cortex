# W1：Vortex 知識點雙向連結索引

## 產出檔（只准建立這兩個）
- `tools/build_vortex_links.py`
- `tools/test_vortex_links.py`
執行 build 後產生 `next/data/vortex_links.json`。

## build_vortex_links.py 規格
Python 3，只依賴 PyYAML 與標準函式庫。讀 `data/vortex/*.yaml`（見共用背景的表），輸出 UTF-8 JSON（`ensure_ascii=False`，`indent=None`，`separators=(",",":")`）。
可用 `python -X utf8 tools/build_vortex_links.py` 執行；repo 根目錄由 `Path(__file__).resolve().parents[1]` 推得，不依賴 cwd。

### JSON 結構
```json
{
  "units": {
    "<id>": {
      "type": "move|drill|tech|error|problem|injury|level|psy|psyc",
      "title": "<標題>",
      "hook": "<一句話，見下>",
      "stroke": "<泳式 key 或空字串>",
      "category": "<category key 或空字串>",
      "category_name": "<該集合 categories 對應的 name_zh，查不到就用 key 本身>",
      "path": "<網址路徑，見網址規則>",
      "record": { 原始資料整筆（psy 的 record 要刪掉 concepts 欄位以免重複） }
    }
  },
  "out": { "<id>": [ {"to": "<id>", "rel": "<關係>"} ] },
  "in":  { "<id>": [ {"from": "<id>", "rel": "<關係>"} ] },
  "strokes": { "<stroke>": {"name_zh": "...", "premise": "<該式 yaml 的 premise>", "moves": ["<move id>", ...依 n 排序]} },
  "categories": { "<type>": [ {"key": "...", "name_zh": "..."} ] },
  "stats": { "units_by_type": {}, "edges_by_rel": {}, "unresolved": [ {"from": "<id>", "ref": "<原始值>", "field": "<欄位>"} ] }
}
```
- 每個 unit 都要在 `out` 與 `in` 出現（沒有連結就是空陣列）。
- 同一對 (from, to, rel) 只記一次；不記自己連自己。
- `in` 必須恰好是 `out` 的反向。

### hook（一句話）取值，依序取第一個非空字串，去掉 `**`，截到 80 字（超過加「…」）
- move：one　- drill：purpose_zh　- tech：summary　- error：misconception
- problem：observable（若是清單取第一項）→ mechanism_summary　- injury：en
- level：tagline　- psy：when_zh → lead_zh　- psyc：phenomenon

### 連結解析（rel 值照寫）
1. `practice`：move → drill。move 的 `drills` 是 drill 的**中文名**清單；以 `name_zh` 完全相等比對。若同名 drill 超過一個，取 `strokes` 含該 move 泳式者；仍多於一個就全部連並記入 unresolved（field=`drills-ambiguous`）。找不到記 unresolved。
2. `fixes`：drill → move。drill 的 `deficiency_fixes` 是整數清單，代表該泳式 move 的 `n`。對 drill 的每個泳式（先轉成 key）找 `{stroke}.move.{n}`，存在就連；該 n 在所有泳式都不存在時記 unresolved。
3. `level`：drill → level。對 drill 每個泳式 key 與每個 `l_target`（如 `L3`），若 `{stroke}.{L}` 是 level id 就連（蛙式、蝶式沒有 L0、L1，找不到不算錯誤、不記 unresolved）。
4. `ref`：`cross_ref_ids`（tech、error、problem）中每個 id；目標必須存在於 units，否則記 unresolved。
5. `ref`：problem 的 `links.technical_analysis[]`、`links.drills[]`（drill 用 id）。`interventions`、`water_interventions` 不是 Vortex 單位，略過不記。
6. `ref`：injury 的 `links.mechanism_link_ids`、`technical_link_ids`、`perception_link_ids`（可能是 null 或空）。
7. `part_of`：psyc → 所屬 psy。
8. 任何其他欄位的文字都不要做模糊比對，只解析上面列出的欄位。

`strokes`：6 式各一筆，moves 依 n 排序。`categories`：drill、tech、error、problem、injury 各自的 categories 清單原樣。

執行結束印一行摘要：各 type 數量、各 rel 數量、unresolved 數量。

## test_vortex_links.py 規格
執行 build（import 或 subprocess 皆可）後載入 JSON，逐條 assert，全部通過印 `ALL PASS` 並 exit 0，任一失敗印出原因並 exit 1：
1. 各 type 數量：move 51、drill 179、tech 222、error 104、problem 73、injury 47、level 26、psy 8、psyc 62（數字要從 yaml 重新計算後比對，不要只寫死；寫死值與重算值都要相等）
2. `practice` 邊數 == 所有 move 的 `drills` 名稱總數（103），且 unresolved 中沒有 field 為 `drills` 的項目
3. 每條 out 邊的目標存在；in 恰好是 out 的反向（集合相等）
4. 每個 unit 的 path 以 `vortex/` 開頭、以 `/` 結尾，且全部唯一
5. 至少 140 個 drill 有 `fixes` 邊
6. 每個 drill 至少有一條 `level` 邊，或其所有泳式都沒有對應 level（udk、starts-turns 沒有 level）
7. JSON 中找不到字串 `map[`
