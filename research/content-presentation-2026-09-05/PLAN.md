## 1. 目標狀態

**每個現有內容單位都有可追溯的呈現去向，讀者能由任務、主題或來源找到它，分辨可用結論與適用邊界，並能繼續閱讀、比較或練習。**

研究最後須回答七題：

1. 全站到底有哪些內容？哪些只是同一資料的不同入口？
2. 讀者有哪些目的、如何稱呼想找的東西？第一次探索、已知目標查找與反覆使用者，分別在哪裡迷路？目前入口漏掉了什麼？
3. 查一個答案、理解一個主題、比較幾種選項、複習與自測，各要什麼版型？
4. 讀者能否看出內容來源、推論層級、限制與下一步？
5. 哪些問題只要改入口或版型，哪些需要回 canonical 補內容？
6. 哪種組織方式能涵蓋更多真實需求，並讓人預判點進去會得到什麼？選定後如何拆成可驗收的實作批次？
7. 已規劃的新專題、操作工具、大型文本、版本與跨庫關係加入時，能否沿用既有閱讀結構？若候選內容未加入，現站是否仍完整？

受眾暫定為「站主本人使用，也讓外部讀者讀得懂的公開工作知識庫」，其比例尚未確認。已確認的使用者意見是「入口不直覺、六個任務不足以代表需求」；後續不能把舊首頁文案當需求證據。需求研究允許沒有明確任務的探索、跨主題串聯、按來源閱讀等情境，不要求訪客先選身份，也不預定每個需求都要變成首頁按鈕。

## 3. 怎麼研究大量內容

### 3.1 三層覆蓋，分開報完成率

**A. 全量結構盤點：100% 頁面、100% 資料集合。** 本次已完成 81 頁／68 檔的檔案級快照。下一步抽取每個原生知識單位的 ID、類型、來源、分類、渲染去向與搜尋入口，並掃全部實際路由、錨點、錯誤與空容器。YAML 的 categories／sources 不是知識條目，閃卡也不是額外的一篇文章。

**B. 全版型檢查：每種呈現機制都有人看。** 25 個具名 layout 各至少一頁；default 分成首頁、書庫列表、Vortex 列表與散文頁，先至少四頁。再補足其餘五個泳式、CSCS ch15／ch16 邊界頁，預估至少 36 頁做桌機／手機及互動巡檢。實際 default 路由若分出更多行為就追加，不為守數字省略。

**C. 分層語意深讀：按內容用途抽，不按檔案大小平均切。** 保留上下文、來源和例外；對未深讀者標 `not_sampled`。模型讀過摘要不等於讀過全文，結構驗證通過也不等於主張正確。

清冊與內容品質分開作業，源自 [NN/g 的 inventory／audit 區分](https://www.nngroup.com/articles/content-audits/)；上述比例和抽樣數是本站的研究設計，並非該來源給出的通用門檻。

### 3.3 清冊與發現的格式

`unit-inventory.jsonl` 每筆至少有：

```text
unit_id / origin_id / owner_repo / source_path / yaml_path_or_locator
domain / content_type / title / reader_task / controlled_tags / aliases
source_ids / evidence_status / publication_status
rendered_urls / anchor / entry_routes / search_surfaces
source_hash / observed_at / review_depth / disposition / finding_ids
```

有既有 ID 就沿用；跨庫使用 namespace，不能用重寫標題產生新 ID。缺 ID 的舊資料先用 `source_path + YAML path` 作研究定位並標 `unstable_locator`，不得偷偷改 canonical。`disposition` 只用「保留、重排、補入口、待上游補內容、候選合併、研究排除」；排除須有原因。重複視圖連回同一 `origin_id`。

每項重要建議記 `affirmative_conclusion`、`works_when`、`fails_when`、`how_to_identify`、`action`、`remaining_boundary`，並連到檔案／節點／頁面觀察。規範、目前實測、研究推論、真人結果各有獨立欄位。不要把「來源登錄 verified」當成「本段主張已被證實」。

### 3.4 先發現需求與用語，再設計入口（新增 W1b）

**需求數量不由現有六個捷徑、四個領域或本計畫的十二道題決定。** 每個內容集合都要回查它能回答什麼、讀者可能如何進入；同時允許讀者提出現有內容尚未支持的目的，列為缺口而非憑空補內容。

1. **內容由下往上整理**：各內容族產出問題、對象、概念、關係、可做的事及必要前提；保留來源 ID。分類探索包不附現有四領域標籤，來源路徑另外供驗證，不拿 repo／書籍目錄當分類答案。
2. **從真實使用經驗收集需求**：先讓站主／參與者描述上次想查什麼、從哪開始、用了什麼詞、最後需要什麼；先不展示首頁。模型補的情境標 `inferred`，真人陳述標 `reported`，實際行為標 `observed`，不能混稱使用者研究。
3. **覆蓋不同查找情況**：知道確切名詞、只會描述現象、不知道站上有什麼、想沿主題學下去、要比較／串聯、找來源／限制、重返已讀內容等只作檢查提示，允許新增與多值，不把它們直接固定成七個入口。
4. **開放分組與命名**：用代表內容的中性標題卡，讓人自行分組並命名，可多重歸屬、可留「不知道放哪」。先小規模試卡片是否看得懂，再擴大；不同人分法不一致時保留差異，不強湊單一樹。方法參照 [NN/g card sorting](https://www.nngroup.com/articles/card-sorting-definition/)，小型訪談結果不宣稱已量化整個受眾的分類偏好。
5. **另測入口是否直覺**：看到標籤先描述預期內容，再揭示實際目的地比對；記誤解、重疊、不認識的縮寫與「不知道點哪」。之後用簡化選單做尋找測試，最後在頁面原型測第一點擊與可發現性。方法參照 [NN/g tree testing](https://www.nngroup.com/articles/tree-testing/)；文字樹測不到完整視覺效果，不代替頁面測試。

`needs-register` 記：`need_id / evidence_type / reader_words / context / desired_outcome / known_terms / content_ids / current_route_or_gap / alternative_routes / uncertainty / test_status`。分類詞彙另記讀者說法、站內說法、同義／歧義與不適用範圍。

每個現有集合均需有需求映射或「尚無證據」紀錄；每個已確認需求均需有可達路徑或明列內容缺口。每輪新增情境都測能否被方案接住；保留一部分未用於設計的題目做最後驗證。六個既有捷徑沒有優先席位，不能用它們的成功率代表全站需求覆蓋。

## 4. 預備呈現方向與比較方法

最新逐內容族呈現、首頁與內頁設計、網站形態比較見 [WEBSITE_STUDY](WEBSITE_STUDY.md)；初次觀察保留在 [BASELINE](BASELINE.md)。版型家族不決定首頁分類。架構研究遵循下列原則：

1. **首頁與分類重新推導。** 全站都能被探索，局部捷徑不能取代完整檢索；分類數、名稱、首頁布局、全域導覽與搜尋的主次由 W1b 的需求與用語證據決定。
2. **查詢、理解、操作、比較、自測用不同呈現。** 查詢先給短答案及精確落點；理解用有定位的連續長文；練習呈現條件／步驟／觀察；比較提供可同時看的表；自測可主動遮答。用 [Diátaxis](https://www.diataxis.fr/start-here/) 辨別不同閱讀需求，五種本站版型是研究推論，不是照搬該框架的四分法。
3. **同時研究瀏覽與搜尋。** 比較知道關鍵詞與不知道該搜什麼的情境；全域搜尋、主題／對象索引與情境入口都是候選。現有 Vortex 搜尋範圍問題仍要處理，但改一個標籤不能代表入口問題已解決。
4. **來源與限制靠近具體結論。** 展開可以放細節，適用條件與安全前提要就地看見；研究內部狀態不直接變成讀者一排機器標籤。
5. **共用閱讀與操作規則，保留必要差異。** 統一「我在哪、怎麼查、怎麼返回、怎麼看來源」，再比較書本是否保留識別樣式。長文不為縮到三屏任意切碎；先測目次與精確錨點。

不建立空的分類容器；[Diátaxis 的實作指引](https://www.diataxis.fr/how-to-use-diataxis/) 本身也不要求先造空的四大區。

### 6.1 十二個既有回歸種子（不是完整需求集）

### 6.2 分開驗證「能找到」「看得懂」「學會了」

先記入口預期與實際內容是否相符、是否理解可探索範圍、是否出現「不知道點哪」；操作再記第一點擊、成功與否、到目標時間、錯路／回退、條件與來源轉述、協助次數。探索情境記讀者能否說出本站有哪些相關內容、發現值得繼續看的內容及返回，不能只用命中指定頁衡量。原型各跑兩輪，暫定每輪 5–8 名實際／潛在使用者，屬找問題的小型質性研究，不代表分類或需求的族群統計；W1b 分組研究的樣本需求另定，不套用這個人數。原型順序交錯並保留未見題目。

測試方法參照 [GOV.UK moderated usability testing](https://www.gov.uk/service-manual/user-research/using-moderated-usability-testing)。AI 可先模擬走查以發現假設，不作為真人成功率。若要聲稱「記得更牢」，另設延後提取測驗與比較條件；本案先驗證自測流程可用。

暫定決策目標：核心任務每題至少 4/5 次獨立完成；安全與來源誤讀零嚴重案例；比現況少走錯路、完成時間不退步。未達到時按實際人次報告，不能只報平均掩蓋某一任務失敗。這些是專案目標，不是通用 UX 標準。

**更簡單的研究路線存在：** 先用中性內容卡、簡化分類與入口名稱測試，再投資完整頁面原型；不把修修舊入口當簡化研究的方式。新資訊架構可以沿用 Hugo、內容 ID 與來源，不需先遷移平台。
