# 教練工具（學生紀錄＋家長查看）規劃書

> 2026-10-15。使用者需求：做成比靜態 HTML 更好的介面；自動記錄練過的課表與學生 PB；選學生自動帶入 PB；記錄所有學生狀況；家長可以看。
> 使用者定：只有自己一位教練、不打算給其他教練用；家長要能用；不做個資法文書，**唯一要做好的是資料安全**。

---

## 1. 架構決定

| 決定 | 內容 | 理由 |
|---|---|---|
| 介面放哪 | **my-site 新增教練工具頁 `/cortex/coach/`**（家長頁 `/cortex/coach/family/`），仍由 GitHub Pages 發布 | 課表引擎（CSS、鐵人、間歇計時、排一週）是 my-site 的 JS，已測、已上線；做在同一個 repo 引擎只有一份，不必兩邊同步 |
| 資料放哪 | **Supabase**（Postgres＋內建帳號；網頁直接連） | 靜態網站不能存資料；Supabase 有帳號系統與資料列層級權限（RLS），權限設在資料庫、不靠網頁擋；免費方案足夠一位教練加家長的量 |
| 資料表 | 照 swim-coach `engine/models.py` 的 students／performances／sessions／feedbacks 設計搬過去，欄位精簡 | swim-coach 已想過的結構不重做；swim-coach 的 Python 出課表程式維持本機研究工具，不搬上雲 |
| 公開工具 | my-site 現有 `/vortex/workout/` 不變（一般人用、不登入、不存成績） | 教練工具與公開工具共用引擎，但入口、資料完全分開 |

**免費方案限制（第三方 2026 年資料，動工前對官方定價頁確認）**：閒置 7 天專案會暫停（資料保留、需手動恢復）；資料庫 500 MB；付費 25 美元／月起不暫停。學生紀錄是文字資料，500 MB 遠用不完。

## 2. 資料安全設計（唯一硬要求）

1. **權限設在資料庫層（RLS）**，每張表都開，預設全部拒絕，再逐條放行：
   - 教練：只能讀寫 `coach_id = 自己` 的資料。
   - 家長：只能**讀**自己被綁定的孩子的資料；不能寫、看不到其他孩子、看不到教練的私人註記。
   - 沒登入的人：什麼都讀不到。
2. **不開放註冊**：Supabase 關閉公開註冊。家長帳號由教練在後台邀請（輸入家長 email → 家長收到登入連結）。就算有人拿到網頁程式碼，也註冊不了、讀不到。
3. **登入方式**：教練用 email＋密碼＋兩步驟驗證（TOTP，用手機驗證 App）；家長用 email 登入連結，不用記密碼。
4. **金鑰**：網頁只放 Supabase 的公開金鑰（anon key，設計上就是公開的，安全靠 RLS）；管理金鑰（service_role）**永遠不進網頁、不進 git**。
5. **學生資料永不進 git**：測試只用假資料；repo 裡沒有任何真實姓名或成績。
6. **權限要有測試證明**：寫一組自動測試，用「教練／家長 A／家長 B／未登入」四種身分實際連資料庫，驗證家長 A 讀不到家長 B 的孩子、家長寫不進任何東西、未登入讀不到任何東西。這組不過不上線。
7. **教練私人註記分開放**：教練對學生的觀察（例如心理狀況、對家長不講的判斷）放在家長讀不到的獨立欄位或表，不靠前端隱藏。

## 3. 資料表（精簡版）

| 表 | 欄位重點 | 誰讀／誰寫 |
|---|---|---|
| `students` | 姓名、出生年、性別、開始訓練日、目標、`coach_id` | 教練讀寫；家長讀自己孩子 |
| `guardians` | 家長帳號 ↔ 學生（多對多） | 教練寫；家長讀自己那幾列 |
| `performances` | 學生、日期、泳式、距離、池長（短／長池）、秒數、場合（比賽／測驗／練習）、備註 | 教練讀寫；家長讀 |
| `workouts` | 學生（可多位）、日期、課表內容（沿用課表工具的存檔格式）、實際完成紀錄（計時器的每趟秒數）、教練給家長看的一句話 | 教練讀寫；家長讀 |
| `coach_notes` | 學生、日期、私人觀察 | **只有教練** |
| `profiles` | 帳號、身分（coach／guardian） | 自己讀；教練讀全部 |

鐵人學生：`performances` 多一種「泳段成績」（賽距＋出水時間），對應課表工具已有的泳段成績換算。

## 4. 功能分期

### P1　資料層與權限（先做、先驗）
- 建 Supabase 專案（**需要你登入建立帳號，這步我沒辦法代勞**；建好後把專案網址與公開金鑰給我，管理金鑰你自己留著）。
- 資料表 SQL、RLS 規則、關閉公開註冊、教練帳號開兩步驟驗證。
- 四身分權限測試全過。
- 驗收：權限測試報告。

### P2　教練工具頁
- 登入。
- **學生名冊**：新增／編輯學生，綁家長 email。
- **學生頁**：PB 表（每式每距離最佳、會自動從所有成績算）、成績歷程、練過的課表、私人註記。
- **課表工具接學生**：在排課畫面選學生 → 自動帶入他的 PB（游泳或鐵人模式依學生設定）→ 選主課／排一週照現有引擎出。可一次選多位學生（共用水道功能已有，接上名冊）。
- **練完自動記錄**：間歇計時器結束時按「存成紀錄」→ 課表＋實際每趟秒數寫進 `workouts`。比賽或測驗成績另有快速輸入。
- 驗收：既有 11 套課表測試照過＋新增教練流程測試（用假資料的測試專案）。

### P3　家長頁
- email 登入連結。
- 看孩子：PB 表、成績曲線、最近練過的課表、教練留給家長的話。
- 驗收：家長身分測試（只看得到自己孩子、沒有編輯按鈕、寫入被資料庫拒絕）。

### P4　備份與維運
- 教練頁「匯出全部資料」按鈕（下載加密前的 JSON，你自己存到雲端硬碟）＋「匯入」還原。免費方案沒有自動備份，這是唯一的備份。
- 防暫停：寒暑假停課超過一週時，用一個每 5 天跑一次的 GitHub Actions 排程做一次無害的讀取，讓專案不被判定閒置（只用公開金鑰、讀不到任何學生資料）。
- 使用說明一頁。

## 6. 風險與對策

| 風險 | 對策 |
|---|---|
| RLS 寫錯導致家長看到別人的孩子 | 四身分自動測試，不過不上線；之後每次改表都重跑 |
| 免費專案閒置暫停 | 正常每週使用不會發生；停課期間用排程讀取保持啟用；真的被暫停，到後台按恢復即可，資料不會掉 |
| Supabase 服務本身出事或改方案 | 匯出按鈕保留完整資料；資料表是標準 Postgres，可搬到任何 Postgres |
| 課表引擎改版影響教練頁 | 教練頁與公開頁共用同一份 JS 與同一組測試 |
| 手機在池邊沒網路 | P2 先要求有網路；需要時再加「離線先存、有網路再上傳」 |
