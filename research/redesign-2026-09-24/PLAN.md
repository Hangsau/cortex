日期：2026-09-25。v1（2026-09-24，「手機工具書 app／搜尋優先」）已被使用者修正，全文見 git 歷史 `33be6a3`。

## 0. 為什麼每次都變成修修補補（v1 結論，仍成立）

專案裡有四個錨點，會把任何模型拉回舊結構：
- `CLAUDE.md` 把過去的版面決定寫成規則；
- 驗收腳本斷言舊結構（`home_audit.js` 寫死 4 領域、6 捷徑）；
- 73 份 layout、20 份 CSS（6,618 行）、8 組網路字型，各區各做各的；
- HANDOFF 的待辦全是修補項。

**斷開方式**：
- 新版寫在 `next/`，禁止從舊 layout 或 CSS 複製任何片段；
- 切換時刪除舊 layout、舊驗收腳本與 CLAUDE.md 的版面規則段。

## 1. 定位（使用者 2026-09-25 確認）

| 區塊 | 誰用 | 要達成的事 |
|---|---|---|
| **Vortex（主力）** | ① 使用者本人：主要工作內容，要自己查得很快 ② 所有拿到連結的人：初學者、家長、進階選手、教練，甚至只是路過有興趣的人 | 誰點進來都讀得懂；內容豐富有趣，自然想一直看下去。**不導流**：不問你是誰、不設分流入口、不強迫走固定路線 |
| **其他系列**（CSCS、兩冊讀本、大腦喜歡這樣學、UST、氣質） | 主要是使用者本人 | 每個系列各自有入口，自己好查閱，並有相關連結點 |

**搜尋降為輔助工具**，不再是主要入口（v1 的搜尋優先撤回）。主要的找路方式有兩種：
- 知識點之間的連結；
- 每個系列清楚的目次。

## 2. 關鍵發現：知識點的連結其實已經在資料裡，網站只呈現了一小部分

2026-09-25 以 `data/vortex/*.yaml` 實測：

**資料裡已有的連結**
| 連結 | 數量 |
|---|---|
| 誤區 → 技術分析 | 178 條 |
| 技術分析 → 技術分析 | 142 條 |
| 問題 → 技術分析／誤區／drill | 108／86／61 條 |
| 動作 → drill（以中文名連結） | 103 條，**103/103 全部對得上** |
| drill → 動作（`deficiency_fixes`） | 142 個 drill 有 |
| drill → 發展級別（`l_target`） | 179/179 |
| 心理概念 → 誤區／介入 | 有（`misconception_refs`、`intervention_refs`） |

**問題：幾乎全是單向的**
| 集合 | 從未被任何條目用 id 連到 |
|---|---|
| drill | 126/179 |
| 傷害 | 33/47 |
| 「找問題」條目 | 73/73 |

另外，167/179 個 drill 自己沒有任何往外的連結。

**這對讀者的意思**：從誤區可以走到技術分析，但從技術分析看不到「哪些誤區在講我」。一個 drill 頁看不到自己練的是哪個動作、能解決哪些問題。讀者停在單一頁，接不下去。

**v2 的核心機制：建置時計算雙向連結。**
- 資料裡每一條 A → B 的連結，在 B 頁都顯示成「A 提到這裡」。
- 以中文名、動作序號、級別代號表達的隱含連結，一律解析成 id。
- **不需要改任何 canonical 內容**，約上千條單向連結就會變成一張互通的網。

## 3. Vortex：每一頁都是入口，每一頁都接得下去

### 3.1 每個知識點一頁

以下每一個單位都有自己的網址，可以單獨分享：

| 單位 | 數量 |
|---|---|
| 泳式與動作（自由式、仰式、蛙式、蝶式、水下海豚腿、出發轉身） | 6 式 51 動作 |
| drill | 179 |
| 技術分析 | 222 |
| 教學誤區 | 104 |
| 問題 | 73 |
| 傷害 | 47 |
| 發展級別（按泳式） | 26 |
| 心理主題與概念 | 8 主題、62 概念 |

呼吸、週期化、水感、關節、動作圖譜維持文章形式。

### 3.2 同一頁由淺到深（取代「依身分分流」）

不問讀者是誰，每頁都照同一個順序排：

1. **一句話抓住人**：用資料裡現成的欄位。
   - 動作用 `one`；
   - 誤區用 `misconception` →「其實是」；
   - 技術分析用 `summary`；
   - drill 用 `purpose_zh`。
   - 誤區本身就是「很多人以為 X，其實 Y」，對路人最有吸引力。
2. **是什麼、怎麼做**：白話的核心內容。家長和初學者讀到這裡就夠。
3. **為什麼**：物理原因與機制（`physical`、`physical_reason`、`mechanism`）。進階選手和教練會往下讀。
4. **證據與來源**：`evidence`、`source_ids`，收在可展開區，網址直接指到時自動展開。
5. **接著看**：依關係類型分組，用白話標題，例如：
   - 「怎麼練這個」→ drill
   - 「常見的錯誤想法」→ 誤區
   - 「背後的機制」→ 技術分析
   - 「練不起來時」→ 問題
   - 「這是哪一級的事」→ 發展級別
   - 每組最多 4 條，多的給「看全部 N 條」。

**分流靠頁面深度，不靠入口**：淺讀的人在第 2 層停下，深讀的人繼續往下，大家走的是同一頁。

### 3.3 樞紐頁（自己查閱的主路徑）

| 樞紐頁 | 內容 |
|---|---|
| **泳式頁**（6 頁） | 動作依序排列；每個動作一行，列出它的 drill、誤區、技術分析的數量與連結。從泳式到 drill 最多點 2 次 |
| **集合清單** | drill、誤區、技術分析、問題、傷害各一頁，可依泳式、類別、級別、器材篩選。篩選器延用各集合 `categories` 的資料，不在 layout 寫死 |
| **Vortex 首頁** | 水感一段話 → 6 泳式 → 「10 個反直覺的誤區」（從誤區資料挑選，連到各誤區頁，專門吸引路人往下讀）→ 發展地圖 L0–L6 → 各集合入口。**不設「你是誰」選擇** |

Vortex 的站內搜尋保留在首頁與清單頁，當輔助工具。

## 4. 其他系列：各自入口 + 相關連結點

| 系列 | 入口頁 | 系列內的連結 | 跨系列連結 |

## 5. 全站結構與視覺

- **首頁**：上半部是 Vortex（主力，完整介紹加 6 泳式入口）；下半部是「書房」，其他系列一行一個，每行有名稱、一句說明、入口。
- **每頁外殼**：站名（回首頁）＋目前系列名（回系列入口）＋路徑列。系列內有自己的目次導航。
- **頁型四種**：文章、條目、清單、工具。任何系列都不准有專屬 layout。
- **視覺方向「野外圖鑑」**（v1 §5 保留）：
  - 理由：圖鑑本來就是一種讓人翻著翻著停不下來、又能快速查的書，正好對上「路人覺得有趣」加上「自己查得快」兩個需求。
  - 日間底色 `#FAFAF7`、字 `#14171A`；夜間底色 `#121416`、字 `#E6E4DF`。
  - 正文 Noto Serif TC 17px、行高 1.8；介面用 Noto Sans TC。
  - 系列識別只用左緣 4px 色帶：游泳 `#0B6E8A`、肌力與動作 `#A23B1F`、學習 `#2F6B3A`、氣質 `#8A6A12`。
  - 字級 14／17／21／27；不用陰影卡片、emoji 圖示、手寫字型。

- 1 個工作單 = 1 次 `claude-m3-lite -p`（精簡版，不讀 CLAUDE.md，所以每張規格必須自足），產出限定在規格列出的檔案；

- 要求每寫完一個檔就存盤；
- 驗收一律看 `git diff` 與實際畫面，不看 exit code。

## 7. 風險與對策

| 風險 | 對策 |
|---|---|
| M3 捏造數字或宣稱完成卻沒產出 | 每單驗收重跑 W1 的斷言與 `git diff`；數字一律用 grep 或腳本重算 |
| 約 900 個 Vortex 知識點頁拖慢建置 | W4 完成時實測；超過 2 分鐘改成只替 drill、誤區、技術分析生成獨立頁 |
| 「接著看」太多變成連結牆 | 每組最多 4 條，其餘收進「看全部」 |
| 隱含連結解析錯（同名 drill、序號對錯泳式） | W1 斷言名稱唯一性；`deficiency_fixes` 必須與 drill 的 `strokes` 組合解析 |
| 舊 Vortex 累積的 UX 決定遺失 | 保留清單：呼吸安全置頂不可收合、導航用 `nav_zh` 短標籤、分類從資料讀、來源白名單、未查證標示；寫進 W4 到 W8 的規格 |
