# Cortex 全站重新規劃（從零開始，不沿用現有版面）

日期：2026-09-24。本檔取代「在現有頁面上修改」的所有路線，包括 2026-09-05 研究提出的「以現有讀本為基底」做法。
該研究的內容盤點（BASELINE、inventory.json）仍然有效，**只沿用資料，不沿用版面結論**。

---

## 0. 為什麼每次都變成修修補補

不管換哪個模型都會走回舊路，因為專案裡有四個錨點，會把任何新進來的模型拉回舊結構：

| 錨點 | 怎麼把人拉回去 |
|---|---|
| `CLAUDE.md` 把過去的版面決定寫成了「規則」 | 例如首頁要四領域、捷徑 ≤6、自訂風格書籍設計模式。新模型讀了只會照規則修 |
| 驗收腳本斷言舊結構 | `home_audit.js` 寫死「4 個 domain、6 個 quick action、19 個目的地」，改掉結構驗收就變紅 |
| 每本書、每個區塊各有自己的版型 | 共 73 份 layout、20 份 CSS（6,618 行）、8 組網路字型。要改只能一區一區改 |
| HANDOFF 的「下一步」都是對現有頁面的待辦 | 新 session 從待辦清單接手，自然就是修補 |

**這次斷開的方式**：新版面寫在獨立目錄，不准從舊 layout 或舊 CSS 複製任何東西。舊的驗收腳本和版面規則在切換時整批刪除（見 §8）。

## 1. 定位（唯一需要你確認的一點）

依據兩份已有紀錄：
- claudehome 專案登錄表：「my-site 是離開電腦時的手機呈現層」
- 首頁文案：「Cortex 是我的工作知識庫」

推導出的定位：

> **Cortex 是你的隨身工具書。主要使用者是你自己，主要裝置是手機**（在池邊、通勤、零碎時間）。
> 其他人（學員、家長、同行）**通常是透過你傳的連結或搜尋引擎，直接進到某一頁**，很少從首頁進來。

這個定位決定了下面所有設計。**若這點不對，整份規劃要重寫。**

## 2. 從使用情境推出結構

| 情境 | 人在哪 | 需要什麼 | 推出的設計 |
|---|---|---|---|
| **查**：池邊要找一個蛙式、不用器材的 drill | 手機、單手、可能手濕、戶外光線 | 3 次點擊內到、字大、高對比 | 搜尋是第一入口；集合可篩選；點擊目標 ≥48px；高對比配色 |
| **讀**：讀一章肌動學、一篇呼吸 | 手機、通勤、會中斷 | 下次回來接著讀、知道自己讀到哪 | 首頁第一區是「繼續讀」；文章頁有進度與目次 |
| **練**：CSCS 選擇題、閃卡、氣質自測 | 手機、零碎時間 | 一鍵開始、記得錯題 | 「練習」獨立成底部分頁 |
| **傳**：把某個 drill 或概念傳給學員或家長 | 對方第一次來，沒有任何背景 | 單頁自己就能讀懂，看得出這是哪裡、還有什麼 | 每個條目都有獨立網址，頁面自足；每頁都有站點外殼 |

**結論：網站形態從「有首頁的文件網站」改成「手機工具書 app」**：
- 殼層固定，內容依型別換頁型。
- 首頁不再當目錄，改成個人起點（繼續、收藏、最近更新）。
- 完整目錄只有一份，放在「目錄」分頁。

## 3. 新資訊架構

### 3.1 全站外殼（每一頁都一樣）

- **手機**：底部固定 4 個分頁，依序是 **首頁｜搜尋｜目錄｜練習**。頂部一條細路徑列，例如「游泳 › 練習 › 蛙式」。
- **桌機**：同樣 4 項改成左側窄欄；中間是正文；右側是目次或旁註。

**依據**：手機 app 的底部分頁是使用者已有的操作習慣（Jakob's Law），4 項也在同屏入口 ≤7 的上限內。

### 3.2 四個分頁

| 分頁 | 內容 |
|---|---|
| **首頁** | ① 搜尋框 ② 繼續讀（最近 3 頁，存在本機瀏覽器）③ 收藏 ④ 最近更新 5 條。第一次來的人沒有紀錄，②③ 改成「這裡有什麼」：系列一行一個 |
| **搜尋** | 全站搜尋（Pagefind 靜態索引）。可依系列、依型別篩選。每筆結果標出所在位置，例如「兒茶酚胺的來源 — CSCS 第 4 章 › 內分泌」 |
| **目錄** | 全站唯一的完整目錄：系列在上，跨系列的集合（練習、誤區、傷害、術語）在下 |
| **練習** | CSCS 選擇題、閃卡、氣質自測、週期化規劃器，加上「只練錯過的」 |

### 3.3 全站只有四種頁型

現在的 73 份 layout 收斂成四種頁型。所有內容都必須歸進其中一種，不再為某本書開專屬版型。

| 頁型 | 用途 | 固定結構 |
|---|---|---|
| **文章** | 要從頭讀的長內容 | 路徑列 → 標題 → 一句導言 → 目次（手機收成浮動「目次」鈕）→ 正文 → 上一篇／下一篇 → 相關 |
| **條目** | 查了就走的單一知識點 | 標題 → 一句話答案 → 固定順序的欄位 → 「出自」連回文章原處 → 相關條目 → 分享 |
| **清單** | 系列目次，或可篩選的集合 | 標題與範圍說明 → 篩選（手機從底部拉出）→ 一行一筆，每行標題加一句說明 |
| **工具** | 需要互動的功能 | 說明 → 開始 → 結果；結果連回相關條目 |

## 5. 視覺方向（全新，不繼承現有配色與字型）

**參照物：野外圖鑑／口袋工具書。** 這類書本來就是拿到戶外邊看邊查的：
- 書側有色塊標籤（拇指索引），一翻就知道在哪一部；
- 版式全書統一；
- 字清楚、對比高。

這三點正好對上池邊、通勤、單手查找的使用情境。

| 軸 | 選擇 | 具體值 |
|---|---|---|
| 年代／物件 | 野外圖鑑、口袋工具書 | 系列識別只用「拇指索引」：頁面左緣一條 4px 色帶，加上路徑列的系列名，不做整頁換色 |
| 材質 | 白報紙內頁；夜間是深色 | 日間底色 `#FAFAF7`、字 `#14171A`；夜間底色 `#121416`、字 `#E6E4DF`（跟系統設定切換） |
| 字型 | 正文襯線、介面黑體，同一設計家族 | 文章正文 Noto Serif TC 17px／行高 1.8；條目、清單、介面用 Noto Sans TC；拉丁字配 Source Serif 4／Source Sans 3（與思源＝Noto CJK 同源） |
| 色彩與對比 | 強調色只出現在拇指索引、連結、選取狀態 | 系列色：游泳 `#0B6E8A`、肌力與動作 `#A23B1F`、學習 `#2F6B3A`、氣質 `#8A6A12`。P1 逐色驗對比 ≥4.5:1（日夜兩版） |
| 密度 | 條目與清單密，文章鬆 | 字級只有 14／17／21／27 四級（比例 1.25）；間距用 8px 格；文章欄最寬 36em（每行約 36 字） |
| 規律與破格 | 嚴格網格，不破格 | 不用卡片陰影、不用 emoji 圖示、不用手寫字型；分組只靠髮絲線與間距 |

**全站 CSS**：一份 token 檔加上四種頁型各一份，目標總量在 1,500 行以內。字型只載 Noto Serif TC 與 Noto Sans TC 兩組，拉丁字依 §5 表格。

## 7. 保留什麼、丟掉什麼

**保留（這些是內容正確性，不是版面）**
- `data/` 全部資料、`sync_vortex.py` 同步管線、`cscs_check.py` 等資料驗收
- 內容規則：
  - 分類標籤一律從資料讀
  - 禁用 `.Summary`
  - 標題綁在實際有值的欄位上
  - 來源註冊表白名單、查不到來源時印出 id、未查證標「未查證」
  - 呼吸安全段落置頂
  - 術語常駐可見
  - 導航標籤用短名 `nav_zh`
- 題庫、氣質計分、週期化規劃器的互動邏輯（JS 核心）
- **所有現有網址**：以 Hugo `aliases` 轉址，已經傳出去的連結不會壞

**丟掉（切換時刪除）**
- 73 份 layout、20 份 CSS、`vortex.js` 的版面分派部分
- `data/home.yaml`、四領域、六捷徑
- 各書自訂風格（mnfl／ust 的書法與手寫字型、emoji 卡片）
- Vortex 專屬左欄與假的「全站搜尋」
- 綁定舊結構的驗收腳本：`home_audit.js`、`audit.js`、`audit_vortex_problems.js`、`audit_book_readers.js` 的版面斷言
- `CLAUDE.md` 中的版面規則段：「首頁：單位是領域」「自訂風格書籍設計模式」「ADM 版型」等，改寫成本檔的四頁型規範

## 8. 施工方式

新站在同一個 repo 平行建造，**舊站照常上線，直到切換那一刻**。
- 新版面放在 `next/`（layouts／assets），透過 Hugo module mount 掛上。
- CI 多建一次，把新版部署到 `https://hangsau.github.io/cortex/next/` 當預覽。
- `next/` 內**禁止**從舊 layout 或 CSS 複製任何片段；有需要的只有資料與 JS 邏輯。

| 階段 | 內容 | 誰做 | 關卡 |
|---|---|---|---|
| **P1 骨架原型** | 殼層、四頁型、token。每種頁型用真實內容做 1–2 例：首頁、CSCS 系列清單＋ch05 文章＋1 條知識單位條目、drill 篩選清單＋1 個 drill 條目、搜尋。部署 `/next/` | `[claude]`（設計判斷，不外包） | **你看預覽定案**。這是唯一的設計決策點；不喜歡只損失 P1 |
| P2 內容接入 | 依 §4 逐內容族寫 content adapter 與欄位對應：CSCS → Vortex → 兩冊讀本 → MNFL／UST → 氣質 | `[delegate: codex]` 每族一單；spec 由 claude 寫，claude 用 `git diff` 與截圖驗收 | 每族完成就 commit |
| P3 搜尋與首頁 | Pagefind 全站索引（中文分詞、依系列與型別篩選、子結果）；首頁「繼續讀、收藏」（localStorage） | `[claude]` | 20 條真實查詢測試（見 §9） |
| P4 轉址與全站稽核 | 舊網址全數轉址；新寫一支驗收腳本，對所有頁面檢查：外殼、320px、對比、焦點、CLS、點擊目標 | `[delegate: codex]` 寫腳本，`[claude]` 審 | 全綠 |
| **P5 切換** | `next/` 成為正式站；刪除 §7 丟掉清單；改寫 CLAUDE.md／MAP／HANDOFF | `[claude]` | 你確認後才切 |

## 9. 驗收標準（寫進新驗收腳本）

**結構**
- 全站只有 4 種頁型；每一頁都有外殼（底部分頁、路徑列）
- 從首頁到任何內容 ≤3 次點擊
- 舊網址 100% 回 200 或轉址

**手機**
- 320px 寬無水平捲動
- 點擊目標 ≥48px
- 內文 ≥17px
- 日夜兩版對比 ≥4.5:1
- CLS ≤0.1
- 尊重「減少動態」設定

**搜尋**
- 20 條真實查詢（例：「兒茶酚胺 來源」「蛙式 不用器材」「間隔重複」「肩胛骨 上旋」「設施 督導」），正解出現在前 3 筆，且結果標出所在位置

**一致性**
- 全站 CSS ≤1,500 行
- 只載 2 組 CJK 網路字型（Noto Serif TC、Noto Sans TC）
- 不存在任何系列專屬 layout

## 10. 風險與對策

| 風險 | 對策 |
|---|---|
| 約 2,500 個條目頁拖慢建置 | P1 先用 CSCS 1,557 條實測；太慢就只生成 drill、誤區、技法，CSCS 條目改用錨點 |
| Pagefind 索引在手機上太重 | Pagefind 是分片按需下載；P3 實測首次搜尋下載量，目標 <300KB |
| 失去各書原本的個性 | 刻意取捨：個性只保留在系列色、封面、導言文字。站內一致比每本書各有風格重要，這正是現在「7 個網站」的病因 |
| Vortex 過去累積的 UX 決定被重做掉 | 已列入 §7 保留清單的內容規則；P2 的 Vortex spec 逐條對照 |
| 範圍大，做到一半停擺 | P1 是關卡：P1 通過前不動任何舊檔；P2 每個內容族獨立 commit，停在哪裡都不影響線上站 |
| 新模型接手後又開始修補 | P5 刪除舊錨點，CLAUDE.md 改寫為四頁型規範；本檔 §0 的根因寫進 CLAUDE.md 開頭 |
