# HIIT 包干提示音與功能檢查（2026-10-08）

使用者在多人出發表發布後要求繼續，並回報包干 HIIT 似乎沒有倒數出發聲，要求檢查完整性。裝置與是否切換 App 尚未回覆；不能把尚未重現的手機現象直接歸因於特定瀏覽器。

## 目標、範圍與使用情境

包干、一般休息、分段、組間及項目間的提示只對應實際下一次出發；臨場改時間後正確重啟倒數；音訊失敗可見且可手動恢復。沿用個人課表、分享格式、暫停與撤銷紀錄，沒有資料遷移。

修改 `next/assets/js/workout.js` 的音訊／倒數生命週期與 `next/layouts/_partials/vortex/workout.html` 的測試音入口。驗收新增 `tools/test_workout_audio.cjs`，沿用 timer／live／studio／goals／lane 五套回歸與全站規格。多人的出發表、canonical 配速處方與其他系列不變。

使用者會在手機／電腦開啟 GitHub Pages。音訊只能在互動後啟用；聲音中斷、頁面切回、暫停續跑需要處理。未實作鎖屏背景服務或背景多階段補跑，畫面明示保持前景。恢復音訊不補播過期提示，以免把過去的出發誤認成現在。

## 已查得的缺口

| 情境 | 舊行為與證據 | 處理 |
|---|---|---|
| 一般包干，保持前景 | 準備／包干各 3 次短音、1 次長音的基準測試通過；不是每次都缺倒數 | 保留正常節奏，以 API 呼叫與時鐘檢查分支 |
| 包干 20 秒，18.5 秒按到牆 | 已經在 17／18 秒播過 3／2；切換等出發會重置記錄，整趟實測 5 個短音，應為 3 個 | 保留同一出發點的倒數記錄 |
| 倒數已開始，在「游」階段加 10 秒 | 舊調秒只清除休息階段的 r 鍵，游泳 s 鍵不重啟；新出發點漏先前播過的秒數 | 統一倒數鍵，依新出發時間重啟 |
| 只有 2 秒休息、延遲到最後一秒才更新 | 舊 forEach 把已過的 3／2 一起補播 | 只播當下剩餘的秒數，不補播錯過秒數 |
| 組間／項目間另設休息 | 包干游泳段仍顯示並播「下次出發」，但實際先進組間／項目間休息 | 改標本趟週期；下一次真正出發前才倒數 |
| 音訊被暫停／中斷 | 只在 openTimer 呼叫 resume，繼續與切回不恢復；Promise 拒絕未捕捉，失敗沒有狀態 | 集中恢復與狀態，處理拒絕；測試按鈕可重建卡住的音訊 |
| 暫停、關閉、撤銷、暫停中跳過最後一趟 | 已排的音調不取消；暫停中完成仍播完成音 | 取消音調與報讀，暫停操作不自動發完成音 |
| 報讀與倒數重疊 | 語音可能覆蓋短音或出發音 | 倒數／出發優先，中止尚未結束的報讀 |

## 技術來源與限制

以目前程式與瀏覽器重現為主要依據。2026-10-08 查 MDN [BaseAudioContext.state](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/state)：`interrupted`／`suspended` 與 `running` 不同，iOS Safari 離開頁面可中斷音訊，需要處理恢復。這支持恢復機制，不能證明使用者當時一定遇到這個原因。

瀏覽器測試記錄 Web Audio 呼叫、頻率、出發時點與取消行為，模擬拒絕、中斷、無支援與恢復 Promise 未回覆。它們不等同真機喇叭、靜音鍵或藍牙實聽；`running` 只標「已啟用，請測試音量」，不宣稱使用者一定聽得到。

## 風險與驗收路徑

- 音訊非同步回覆可能晚於暫停／關閉／重建：用 context 身分與音調版本排除舊結果，恢復失敗不影響時鐘；覆蓋失敗與卡住後再恢復、停止後不補播。
- 已完成／部分完成的訓練不能因聲音修正被重排：timer／live 檢查分段、組數、趟數、rowRest 覆寫、出發週期、撤銷、途中修改、已完成紀錄與暫停扣時。
- 空課表、大量趟數、非法時間與舊存檔：既有 timer／live／studio 回歸；不改匯入／存檔 schema，不新增外部輸入或 LLM 解析。
- 多段倒數與短休息：新聲音測試檢查正常準備、包干、手動／自動到牆、兩秒休息、延長包干、分段、組間／項目間覆寫、暫停續跑、完成音與無音訊降級。
- 手機按鈕新增：320／390／1440px 版面與畫面抽查；測試音不修改儲存課表。
- 發布：先所有回歸及 22 specs／121 舊網址通過，再 commit／push；CI 完成後對正式網址執行新聲音測試。失敗先修原因；需撤回時 revert 本次功能 commit 再部署，無資料還原。
