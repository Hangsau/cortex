# 器材如何加入推薦課表

研究日期：2026-10-07。狀態：研究與可實作提案完成，尚未修改推薦引擎或公開網站。

結論：保留目前七種主課目的，在主課推薦中提供可選的「技術準備」及「器材變式」。先由目的決定內容，再依今天的器材、熟悉程度與泳池條件篩選。器材不必各自變成一套完整課表，也不應只貼上器材標籤就沿用原配速。

本文的搭配表、範例份量、介面與開發順序是專案設計；不是研究證實的最佳處方。來源、主張、條件式決策與矛盾檢查見 [records.json](records.json)，搜尋範圍與存取限制見 [run-manifest.json](run-manifest.json)。

> 使用者後續修正（2026-10-07）：器材份量、配速與時間接受手動設置／處理。下文涉及自動配速、池長、換裝與計時引擎的前置設計，保留為未來可選擴充，不作目前內容與課表示例使用的阻擋條件。器材教學及重要研究寫回站內，自己的文章連結保留，外站連結移除。

## 1. 研究支持哪些原則

| 發現 | 對推薦功能的意義 | 邊界 |
|---|---|---|
| 同速度的 12×50m 自由式試驗中，划手板與蛙鞋條件的乳酸反應低於無器材（C02／S02）。 | 不能把相同秒數視為相同負荷；器材段不要直接套無器材 CSS 或 PB。 | 11 位有經驗男性的急性測試，不提供通用換算比例。 |
| 拉手、踢腿、完整游在研究中是不同任務（C03／S03）。 | 8 字球拉手與踢腿需要自己的努力程度或手動目標。 | 只讀摘要；不能由此推導所有器材的配速係數。 |
| USMS 的呼吸教學將戴管練習接回正常換氣游（C09／S09）。 | 技術準備要帶一段無器材完整游，檢查是否能保留練習重點。 | 教練指引，不是長期技能轉移的對照試驗。 |
| 12 位大學男性泳者的交叉試驗，划手板＋阻力傘衝刺暖身未顯著改善接下來的 25m／50m 表現（REC-C01／REC-S01）。 | 不把阻力暖身當成純速或賽速課的預設增益。 | 單次效果；不能用它否定長期阻力訓練。 |
| 11 週阻力傘研究摘要報告實驗組改善（C04／S04）。 | 進階阻力仍可保留在有監控的專項設計。 | 小樣本、只讀摘要；沒有把組內顯著當成已證實組間優勢。 |
| USMS 編課指引強調每組有目的、指示清楚、觀察個別反應（REC-C02／REC-S02）。 | 每個器材選項說清楚用途、單一提示與移除後觀察項目。 | 實務指引，不是某一課表順序優越的試驗。 |

## 2. 放在推薦課表的哪裡

### A. 主課前的技術準備：優先實作

放在使用者安排的暖身之後、主課之前，落在現有 drill 區。預設不加入；仍保留目前由使用者自行安排暖身、drill、緩和的操作方式。

一個模組包含「器材練習 → 無器材完整游 → 一個觀察點」。器材段只處理一個問題，例如頭位、轉體時序或拉水感受。移除後能否維持才是當天回饋；不能把戴器材變快當成技能已學會。

這個位置適合輕量、已熟悉的技術準備。若是第一次學器材、正在改大動作、做大量踢腿或阻力負荷，就可能已是一個獨立訓練內容；不能一律當作不影響主課的暖身附加品。（REC-D01、REC-D03、REC-D05）

### B. 主課中的器材變式：先限於輕鬆／穩定有氧

使用者選擇後，替換原本部分距離，預覽清楚寫「取代多少完整游」，保留無器材段。先不增加總距離；但必須標示：距離相同不代表生理刺激完全相同。

例如自行設定的 8×100m 穩定有氧，可以提出「前 2×100m 改為熟悉的 8 字球拉手，後 6×100m 維持完整游」。拉手段改用努力程度或當天手動設定的目標，完整游才沿用原本相容的配速。這只是有條件的示範，不是系統現有組型，也不是通用 25% 配額。

若原課目的是維持連續完整游節奏、練踢腿參與或測試進步，替換會改變任務，應保留原課。閾值、純速、乳酸生成、乳酸耐受、賽速第一版均保留主要完整游內容。（REC-D02、REC-D03）

### 七類主課的第一版配置

以下都是設計建議，須先通過泳式、能力、器材與泳池條件檢查。

| 推薦主課 | 可選技術準備 | 主課器材變式 |
|---|---|---|
| 輕鬆有氧 | 呼吸管頭位、熟悉蛙鞋的姿勢練習、合適的浮板踢腿後接完整游 | 可提出少量 8 字球拉手替換；不把它標成原完整游的等效負荷 |
| 穩定有氧 | 同上，挑一個與當日困難相關的重點 | 可提出拉手等變式；若要維持全程完整游節奏則不替換 |
| 閾值 | 少量熟悉的技術準備，避免先做疲勞性的踢腿／拉手 | 第一版保留無器材主課；器材閾值需另有同條件參照 |
| 純速 | 可選非常簡短且熟悉的動作準備；保留主課品質與恢復 | 不預設加入大划手板、阻力傘或牽引繩；進階專項另設 |
| 乳酸生成 | 可選短技術準備，不追加器材負荷 | 保留原主課與完整恢復 |
| 乳酸耐受 | 不累積額外局部疲勞的簡短準備 | 保留原主課；不因選了器材就加組或縮短休息 |
| 賽速 | 有明確技術需求才提示短準備 | 關鍵段維持目標比賽泳式與無器材條件；器材成績不混入原 PB／CSS |

這些分類本身已有足夠入口，無須另開「器材有氧」、「器材衝刺」七套平行選單，也不需要因本功能新增 USRPT 整份課表。

## 3. 使用者實際會看到的操作

1. 沿用目前的訓練目的、泳式、份量選擇。
2. 展開「搭配器材（可選）」：勾今天帶的器材，再選「今天想改善什麼」。未選器材時保留原推薦。
3. 顯示一個最符合條件的建議，可略過；需要時才詢問是否熟悉該練習、今天池長或能否穩定完成該段距離。預覽用途、必要器材、增加／替換距離、努力程度、換器材休息與指南連結，再由使用者加入。

不要一開始要求輸入一整份能力問卷。選項按泳式與器材收斂；沒有審核完成的配對，就保留無器材推薦。不能只因資料庫剛好有同器材 drill 就硬湊。

### 可評估的畫面文字範例

> 主課：自由式・穩定有氧
>
> 今天帶的器材：中央呼吸管
>
> 想改善：換氣時頭部起伏
>
> **主課前加一段：穩定頭位 → 正常換氣**
>
> 2×25m 戴管輕鬆完整游 → 2×25m 不戴管、正常換氣。
>
> 只觀察一件事：拿掉呼吸管後，頭部是否仍能隨身體轉動，減少抬頭。
>
> 增加 100m；無自動目標秒數。每趟到牆後自行按計時器。示範趟間休 20 秒，換器材／接主課留 30 秒，可調整。
>
> 適用：25m 池、已熟悉呼吸管、能正常呼吸並穩定完成每趟。管口維持水面上。看使用方法｜略過｜加入技術準備

數字僅為介面與執行順序的設計示例，不是最佳劑量。器材先放出發端，戴管兩趟回同一端再摘下，避免泳池中央或器材不在的池端換裝。示例將 A 段做完再做 B 段，並未聲稱四趟交替。

若原本主課是 800m，預覽顯示此技術段＋主課共 900m，不含使用者另外安排的暖身與緩和。時間只顯示粗估或待實際計時，不能把無器材配速估值當作器材目標。

50m 池不直接把這個模板變成雙倍距離：原 100m 預算下此模板不適用，需另選經審核且能完成的長池模板，或不加。若使用者改選 2×50m＋2×50m，預覽必須明列新增 200m，且確認每趟距離可完成。（REC-D04、REC-D06）

## 4. 器材的第一版範圍

| 器材 | 建議先提供的功能 | 啟用條件／暫緩項目 |
|---|---|---|
| 中央呼吸管 | 自由式頭位準備，再接正常換氣完整游 | 熟悉排水與水面呼吸；不推薦閉氣或水下持管呼吸 |
| 蛙鞋 | 經審核的姿勢、轉體或踢腿時序模組 | 依泳式與鞋型選；不直接套一般蛙鞋做蛙式腿，不從「有蛙鞋」推定會進階 drill |
| 8 字球 | 拉手／姿勢感受後接完整游；有氧主課可選替換 | 不把高浮力、大幅轉體或不適視為必須完成的課表要求 |
| 浮板 | 使用者明確想練踢腿時的可選段落 | 能保持舒適頭頸位置與正常呼吸；不能因此挪用完整游的配速 |
| 划手板 | 指南與手動設定先保留；之後加入小型、熟悉的回饋模組 | 第一批自動推薦暫緩，先審核尺寸／能力／動作品質條件與現有候選 drill；不是認定器材沒有價值 |
| 節拍器 | 第二階段的節奏控制 | 需先分清單手、完整循環、踢腿的單位，避免將拍頻硬當配速 |
| 阻力傘、阻力／助力繩、原地繫繩 | 指南＋手動／教練設計 | 需要阻力設定、固定點與場地條件；原地繫繩還需要時間型工作段，現有距離列不足以表達 |
| 腳踝帶、複合大負荷搭配 | 暫不自動推薦 | 身體控制與負荷條件尚未足夠結構化 |

先完成少量可追溯模板。第一批候選以自由式呼吸管、蛙鞋姿勢、8 字球拉手及適當踢腿模組為主；各泳式依審核進度加入，未有相容模板時直接保留原主課，不造出表面完整的四式套餐。（REC-D05、REC-D07）

## 5. 現有程式真正需要處理的地方

此段是程式讀取結果，尚未改碼。網站基準 `c6c4c2e641b1f954aae1ec822d744d7b1e326eb6`；canonical 基準 `163eef665933251e3c9f46a87d1c2401fd12f989`。

| 現況 | 加入器材後的影響 | 實作要求 |
|---|---|---|
| `targetOf()` 依模式、強度與 PB／CSS 計算，沒有檢查 `equip`；拉手也不在禁止自動配速的模式內。 | 只加器材標籤仍會得到普通配速。 | 建立共用的配速相容性判斷，覆蓋顯示、計時、手動編輯、分享與 AI brief；不能只修推薦按鈕。 |
| `int: none` 可以不產生配速，但也牽涉目的呈現與自動休息；`autoRest()` 可能重算休息。 | 技術段沒有 PB 時，可能連目的或休息一起失去。 | 訓練目的、配速依據分開表示；模板明定休息，不能因取消自動配速而歸零。 |
| `estSec()` 缺目標時仍用普通 CSS 或預設值估時；有些路徑據此先算出發間隔。 | 粗估容易被誤當成器材目標，或形成過早出發。 | 估時僅供預覽；器材沒有有效目標時用到牆後休息，不自動啟用估算的固定出發間隔。 |
| `goalSet()`／`addMain()` 目前回傳並加入單列；`rowSteps()` 先跑完每列的趟與組。 | 「A×4、B×4」實際是 AAAABBBB，不是 ABABABAB。 | 第一版先用少換裝的 AABB 模組；真正交替時展開成依序的列。不要只在備註寫交替。 |
| `rowRest` 取代跨列的普通趟休，不會相加；最後一列結尾不加休息。 | 寫 30 秒器材轉換不會自動變成原休息＋30 秒。 | 若換裝可在恢復期間完成，跨列休息取恢復時間與換裝時間的較大值；若教練指定先恢復再換裝，才相加。結尾依後續工作段判斷。 |
| `S.course` 介面是「成績的池長」。 | PB 來自 25m 池，不代表今天在 25m 池。 | 今天泳池條件另確認；配速條件需相容。模板檢查完整池長、每段能力與器材所在池端。 |
| `myEquip` 是使用者新增的器材詞彙，不是今天攜帶的清單。 | 不能將「系統有這個名稱」當成現場可用。 | 今天可用器材獨立收集，不以全器材列表當預設持有。 |
| 前端 drill 資料只輸出部分欄位，沒有難度；現有器材標籤也不區分必要／可選。 | 器材與泳式符合，仍可能是進階動作或缺少必要器材。 | 推薦模板獨立標必要／可選器材、能力條件、泳式、目的、來源與觀察點；不直接拿第一條 `how_to` 拼課。 |

程式定位：`next/assets/js/workout.js` 的 `targetOf`、`estSec`、`autoRest`、`goalSet`、`addMain`、`rowSteps`、分享與 brief；`next/layouts/_partials/vortex/workout.html` 的 drill JSON 與成績池長欄位。（REC-C03～REC-C06）

### 既有 drill 的候選審核

- `FrEL1` 為 elite，器材標記包含蛙鞋與呼吸管，原示例較長；不能當成「有蛙鞋即可做的入門六腳一划」。若新設簡化模組，須明確當成新變式。
- `Br8` 的文字有「可戴」呼吸管，器材列表卻列入呼吸管；目前標籤不足以判斷必要條件。
- `Sc7` 的泳式分類涵蓋仰式，但練法為面朝下；泳式標籤不是可直接替換主課動作的保證。
- `Fl25` 是進階且含自由式輕踢腿變式，不能直接當一般蝶式兩次踢腿時序練習。
- `UDK4` 含進階水下距離情境；不能因有節拍器就自動推薦。
- `FrPad1` 與 `Br5` 延續前輪待複審，先排除自動推薦。其他候選的固定配額及概括性功效也需逐項複審。

上述是資料品質與推薦適用性判斷，不表示刪除整個練習庫。canonical 與網站同步資料仍按原本來源流程維護，不手改產生檔。（REC-C07、REC-D07）

## 6. 第一版資料與執行流程

器材指南繼續負責詳細說明；推薦使用人工審核的結構化小模板，連回指南章節與 drill。不要每次從整篇指南臨時抽句拼課。

每個模板至少有：穩定 ID／版本、支援目的與泳式、必要與可選器材、可觀察的能力條件、適用池長與換裝位置、按順序的段落、加入或替換策略、距離預算、配速依據、趟休／跨段休息、單一提示、移除器材後的觀察點、停止／退階條件、來源與設計理由。

執行順序：

```text
選主課目的＋泳式＋份量
  → 篩今天器材／技術重點／能力／池長
  → 提出一個合適模板或保留原課
  → 預覽加入／替換的列、總距離、休息與配速依據
  → 使用者加入，成為普通可編輯課表列
  → 用既有計時器依實際順序執行
  → 可選回饋：無器材仍保留重點／感覺不明顯／不適或無法完成
```

第一版以努力程度與明確手動目標為主，不必先建器材 PB 大型資料庫。將來若有同泳式、同模式、同器材設定與池長的測試，才設計獨立參照，不能預設和無器材成績互換。PB 仍遵守現有不持久保存的使用者偏好。

生成結果應保存當次模板版本與設定摘要；之後模板更新不重寫既有課表。舊課表若有器材與自動配速，執行前標示需確認，不在讀檔時偷偷重算或清空使用者手填秒數。器材／模式／距離更動後，手動目標也需標示是否仍適用。當次計時快照不因重新推薦被覆蓋。

之後接 AI，可以讓它解釋這一份已確定的結果：「為何選此器材、此段的目的、何時不適合、拿掉後看什麼」。AI 使用同一份來源與規則，不自行編造配速換算、療效或最佳占比。這階段無需付費 API 就能完成核心功能。（REC-D08）

## 7. 實作順序與驗收

1. 先處理配速相容性、手動目標來源、估時與出發間隔的分離；補模板必要／可選器材及能力欄位。
2. 完成少量模板的來源／動作審核，再接可選技術準備、份量預覽與指南入口。
3. 用真實泳池動線驗證，再開放有氧主課替換；進階阻力、時間型原地段與自動個人化另外設計。

| 情境 | 必須觀察到的結果 |
|---|---|
| 不選器材／沒有相容模板 | 七種原主課可照常使用，不被迫增加 drill。 |
| 缺必要器材、只有自訂未知器材、尚不熟悉練習 | 不自動拼替代品；可略過並查看適用說明。 |
| 有普通 PB／CSS，加入器材 | 器材段不誤用普通自動配速；原完整游段仍正確。 |
| 沒有 PB | 仍顯示目的、努力程度及明確休息；不以估時補出固定出發間隔。 |
| 器材／模式／距離編輯、分享、列印、AI brief | 使用一致的配速適用性與依據；手動目標不被冒充成研究或 PB 推算。 |
| A×2、B×2 技術段 | 預覽和計時均為 AABB；若要求交替，實際列與計時都必須是 ABAB。 |
| 普通休息大於換裝時間 | 換裝不縮短必需恢復；末列是否有休息依是否接下一段判定。 |
| 25m 模板用在 50m 池、距離預算不足 | 不半池換裝，不自動加倍曝露距離；給出適用模板或略過。 |
| 器材在出發端 | 預覽的穿脫位置可實際執行，不在缺器材的池端要求換裝。 |
| 新增技術段／主課替換 | 增量與替換量正確；不把等距替換稱作等效生理刺激。 |
| 舊存檔與正在計時的課表 | 載入不破壞原資料，重新推薦不覆蓋當次執行；需確認的配速明確顯示。 |
| 手機 320／390px | 能完成選擇、看懂增量與提示、加入或略過；指南往返保留目前編輯。 |

上述為未來功能的驗收規格，並非本輪已跑過的產品測試。本輪只驗證研究 records 格式、來源完整性、引用關係及提案與現有程式的對應。後續啟動實作時，再依 plan-check 做跨檔案影響檢查。（REC-D09）

## 8. 尚未解決的界線與更新條件

- 本輪是針對整合問題的定向研究，沒有系統性搜尋所有器材、所有泳式與族群；不做長期效果排名。
- 不以年齡或「精簡」按鈕代替能力判斷。初學者若不能穩定完成整池距離，不能直接拿本頁 25m 示例套用。
- 技術準備是否改善當天無器材動作，需泳者回饋或教練觀察；一次主觀改善不能宣稱長期學習效果。
- 若泳池試用發現頻繁換裝拖慢、趟長不合適、提示無法理解，先修模板及份量，再考慮擴充器材數量。
- 若增加可靠同條件器材測試、已審核的其他泳式模板或時間型計時能力，再擴大自動推薦範圍。證據不足的部分保持條件式建議，不輸出精確而無根據的目標秒數。
