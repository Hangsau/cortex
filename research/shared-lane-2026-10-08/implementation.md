# 單水道多人出發表實作

使用者已核准「先放入」。沿既有研究結論執行，不另加確認流程。

## 目標與範圍

在原排課頁加入可手動調整的名單、單組距離／趟數、休息範圍、批次與出發表。讀取既有目的推薦的單組組型，逐人時間由使用者提供，產生第一趟、下一趟、最後到牆和實際休息。

影響：workout.html 與新 workout-lane partial、workout-lane.js、workout.js 唯讀 recommendation 介面、studio 導覽與 hash、workout.css、針對本功能的計算與瀏覽器檢查、MAP/HANDOFF/研究記錄。

不改：既有 PB、個人課表／分享格式、HIIT 或游泳計時狀態、canonical 資料、其他頁型。無新 API 或 AI。所有說明在站內，不新增外站連結。

使用情境：手機／桌面開啟靜態 GitHub Pages。名單及秒數僅本頁記憶體，不持久保存、不進網址；複製動作由使用者觸發。不新增排程、背景計時或離線同步，因此無休眠補跑問題。

## 風險與應對

| 風險 | 檢查／處理 |
|---|---|
| 人間間隔被錯扣成休息、末人未完成即換批 | 已知四人算例、逐人事件恆等式、單趟／末趟與輪流模式檢查 |
| 無解仍被標成可用或分批等待未算 | 顯示實際休息與不相容原因；輪流用完整一輪的週期；手動週期不足以游完／清道時拒絕生成 |
| 推薦改距離仍沿用舊時間 | 池長、單趟距離或游法變動時清空每人參考時間；不讀個人 PB 填全隊 |
| 人名／目的注入 HTML | 所有結果字串跳脫；長度限制；UI 測試惡意字串、超長字、空值及非法秒數 |
| 新區塊被 studio 搬頁機制遺漏 | 原始頁直接入口、pace attach、hashchange 與初次深連結測試 |
| 私有名單寫進個人課表或活動計時 | 測 localStorage／分享前後一致；不修改個人 timer seq；重載清空名單秒數 |
| 手機表格溢出 | 表格容器局部捲動，名單欄位換行；320／390／1440px 驗證與畫面抽查 |
| 剪貼簿拒絕導致結果丟失 | 降級顯示可選取文字，按鈕狀態清楚；表單更動時清除舊結果與複製內容 |
| 發布時分支漂移 | push 前 fetch 查分歧，不強推；失敗修復後重跑相關檢查 |

無持久格式遷移；大資料限制於 24 人／200 趟，限制屬工具規模而非水道安全容量。頁面中斷會失去本次名單，頁面明示，使用者可先複製出發表。計算沒有非同步共享狀態；剪貼簿等待後先檢查結果版本，避免過期回覆。

回復方式：保留原課表狀態，若需撤回，以本次功能 commit 的 revert 再部署；不移除歷史或改既有網址。新功能與個人計時完全分開，所以不需要資料還原。
